## CSP inventory and decision

The source components and complete Astro production output were inspected. The build produced 26 inline script blocks, 20 unique byte sequences, across 17 HTML files:

- page-specific JSON-LD generated by `SiteMetadata.astro`;
- the Astro-processed shared header behavior;
- the Modern contact-page behavior;
- the review-page behavior.

Cloudflare Web Analytics is injected as a dynamically versioned external script from `https://static.cloudflareinsights.com`; its network endpoint uses `https://cloudflareinsights.com`. Cloudflare challenge/Turnstile capability requires the narrowly retained `https://challenges.cloudflare.com` script/frame/connect origin. No `unsafe-eval` is allowed. The build had no inline `<style>` blocks but retained five authored `style` attributes.

The `script-src` policy changed from:

```text
'self' 'unsafe-inline' https://static.cloudflareinsights.com https://challenges.cloudflare.com
```

to a deterministic build-finalized policy:

```text
'self' <SHA-256 for every actual built inline script> https://static.cloudflareinsights.com https://challenges.cloudflare.com
```

The build finalizer inventories the actual generated HTML, calculates sorted SHA-256 CSP sources, replaces a single template placeholder in `dist/_headers`, rejects an empty or unfinalized policy, rejects `script-src 'unsafe-inline'`, and enforces the Cloudflare Pages 2,000-character header limit. Fixed/reused nonces and an edge Worker nonce architecture were not introduced.

`style-src 'unsafe-inline'` was retained separately because current authored inline style attributes require it. Removing those styles would expand this bounded maintenance into unrelated component churn; Cloudflare/Turnstile compatibility also remains safer under the existing style policy. No `unsafe-eval` or broader script origin was added.

## Static asset cache decision

The starting production build contained only these `dist/_astro/*` assets, all content-fingerprinted:

- `BaseLayout.CPy6YP47.css` (9,118 bytes)
- `ModernLayout.Dz4hQskr.css` (42,437 bytes)
- `release-16-12.Durm6cQB.css` (4,138 bytes)

The route-specific policy changed from the platform's observed `public, must-revalidate, max-age=14400` behavior to:

```text
/_astro/*
  Cache-Control: public, max-age=31536000, immutable
```

The policy applies only to fingerprinted `/_astro/*` output. It does not apply to HTML, mutable public images, `/review/*`, `/api/*`, or PDFs. `/review/*` and `/api/*` retain `no-store`. The repository's `/forms/*.pdf` rule remains `public, max-age=3600`; the current production zone raises the observed PDF max-age to 14,400 seconds, and the monitor records that established environment-specific behavior without changing it.

## Rollback

Repository rollback is a normal revert of the maintenance commit before or after merge. If the candidate is not merged, closing the PR leaves production code unchanged.

Cloudflare rollback uses the exact recorded prior settings:

1. Disable HSTS (or set max-age to zero), leaving includeSubDomains and preload off.
2. Set Minimum TLS back to `TLS 1.0 (default)`.
3. Turn Always Use HTTPS off.
4. Recheck apex HTTPS, direct HTTP-to-HTTPS, and direct `www`-to-apex behavior.

HSTS rollback is not instantaneous for browsers that have cached the 30-day policy. HTTPS must continue to be served until the cached max-age has elapsed for affected clients.
